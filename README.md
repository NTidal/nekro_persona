# 三档背景记忆 (nekro_persona)

> NekroAgent 插件 · 让角色记住**她是谁、经历过什么、这个世界是什么样的**
> 分层注入 + 按需检索 + 硬预算；**好感度是解锁标尺**——关系没到，有些事她就还不想说。
> **2.0 起**：前 3 档是手工策划的「种子」（模型不可改）；**tier4 是「生长」**——角色在运行时自己沉淀的身份锚点（身份）与频道笔记（功能），
> 并具备**种子包 / 生长包分离导出**：角色定义可公开版本化，「这一世活过的痕迹」可整体迁移备份。

版本 **2.2.17**　作者 **NTidal**　许可 **GPLv3**

---

## 一、为什么分三档

提示词预算是有限的，而「该记住的事」重要性差别极大：基础设定每轮都得在，几十条往事不可能每轮都塞进去。

所以按**「什么时候该想起来」**分档：

| 档位 | 内容性质 | 何时注入 | 默认预算 | 匹配方式 | 好感度门槛 |
|---|---|---|---|---|---|
| **1 档 · 身份** | 她是谁、日常、基本设定 | **每轮直接注入** | 2000 字符 | 不匹配，全量注入 | `min_favor` |
| **2 档 · 往事** | 她亲历的细节 | **提到才检索** | ≤2 条 / 500 字符 | `triggers` 关键词优先，未命中走向量（阈值 0.35） | `min_favor` |
| **3 档 · 世界知识** | 她之外的人 / 地点 / 势力 / 术语 | **提到才检索** | ≤3 条 / 700 字符 | 同上 | **不受门控** |

上表的预算与阈值**全部可配置**（见第十节），也可在 WebUI「概览」页直接改。

几个关键取舍（都是实测调出来的）：

- **2/3 档的检索 query 用「最近消息原文」，不用 LLM 生成**——LLM 生成的 query 是文档腔，实测召回 0.32 vs 原文 0.49
- **2 档偏精确**：1 档已经兜住身份，2 档漏召回不致命，误召回反而会把话题带偏
- **3 档不受好感度门控**：世界常识不该因为不熟就不说；但用 `familiarity`（熟人 / 听说 / 仅传闻）控制语气分寸，角色不该「全知」
- **1 档静态、2/3 档多数轮次为空** → 系统提示词前缀缓存友好
- **1 档没有阈值 / 扫描项**：它是「每轮直接注入」的身份级记忆，不参与检索，只受字符预算约束

### 种子 vs 生长（tier4 生长层，1.7.0）

上面三档是**手工策划的「种子」**——告诉模型「他是谁」，静态、且**模型不可改写**。
1.7.0 起再加一层 **tier4「生长」**——记录「他怎么长成现在这样」，由角色在对话中自己沉淀：

| | 种子（tier1/2/3） | 生长 · 身份锚点（tier4 `kind=anchor`） |
|---|---|---|
| 谁写 | 作者手工 | 角色运行时（经 `沉淀身份锚点` 工具） |
| 内容 | 「他是谁」 | 这一世形成的自我认知 / 长期承诺 |
| 可变性 | 模型不可改 | 只增、**绝不回写种子** |
| 作用域 | — | 全局、永久、跨频道 |
| 约束 | 字符预算 | **硬频率闸**：日≤N、间隔≥M、总量≤上限 |

四条铁律：①审慎累积不每轮都长（频率闸）②只增不改种子 ③作者可审计（WebUI 看/删/调 + 每次写记日志）
④触发可见（显式工具调用，非后台静默改写）。空 tier4 时注入块为空，`persona_prompt` 与 1.6.4 **逐字节一致**。
（同一层内部还有 `kind=note`——频道级、可过期、受好感度门控的功能笔记，用于接替原「备忘录」；阶段 B 迁移，见仓库根目录的 tier4 设计稿。）

## 二、一轮对话里发生了什么

```
用户消息
   │
   ├─ 1 档：全量注入（身份级，超预算按 weight 截断）
   │
   ├─ 2/3 档：用最近消息原文做匹配
   │     ├─ triggers 关键词命中 → 直接取用
   │     └─ 未命中 → 向量检索（独立预算，3 档不与 2 档抢 top-N）
   │
   ├─ 门控过滤（见第三节）
   │     ├─ 达到 min_favor → 进正文
   │     └─ 未达到       → 列入「暂时不想细说的事」
   │
   └─ 渲染成「#你的记忆」「#你知道的事」两段，交给模型
```

记忆数据改完不需要重启：WebUI 点重载，或让 AI 调用「重新加载背景记忆」。

## 三、好感度：解锁标尺

好感度在本插件里的**主要作用是决定「哪些事现在能讲」**：

| 机制 | 说明 |
|---|---|
| `min_favor` | 每条 1/2 档记忆的门槛。没到就进不了正文，改列入回避块 |
| `stages` | 分数落在哪个区间，决定当前档位名 |
| `stage_guides` | 各档位的**互动指引**（注入给模型，调节亲密度与语气） |
| `avoid` | 未达标记忆所属的回避块标题与说明 |
| `rubric` | 注入给模型的评分参考（什么行为值多少分） |

**默认档位（`favor.json` 的 `stages`）**

| 分数区间 | 档位 | 含义 |
|---|---|---|
| ≤ −60 | 排斥 | 只给最表面的回应 |
| −59 ~ −20 | 保留 | 礼貌但克制 |
| −19 ~ 19 | 中立 | 公开层 |
| 20 ~ 59 | 亲近 | 可流露脆弱面 |
| 60 ~ 84 | 偏爱 | 可讲最私密的事 |
| 85 ~ ∞ | 特别亲密 | 关系已确立，语气最亲密（仍守角色边界） |

> 档位表本身可编辑（WebUI「规则与门控」）。`max` 写成 `999` 表示该档为最高档（界面上显示为 `∞`）。

分数由 AI 在对话中**自主调整**（沙盒方法「调整好感度」），也可用群聊命令手动干预。

**改动分数有约束层**，防止模型刷分或情绪化乱加：

| 约束 | 默认 | 作用 |
|---|---|---|
| 单次幅度上限 | ±5 | 一次调整最多这么多 |
| 同用户最小间隔 | 120 分钟 | 两次调整之间的冷却 |
| 每日净加分上限 | +5 | 一天内净增总分 |
| 每日净扣分上限 | −10 | 一天内净减总分 |
| 边际递减 | 开 | 分数越高，同样行为加分越少（至少 +1） |
| 要求具体理由 | 开 | 理由只有「聊得很开心」这类氛围词时不予加分 |
| 索要式拦截 | 内置 | 用户直接索要加分会被拒绝 |

> 每日额度与最小间隔由档案里的 `day_key` / `day_net` / `last_adjust_at` 三个字段**持久化记录**，
> 不再从「最近 8 条变动记录」反推——高频调整下旧记录会被挤出窗口导致统计失真。
>
> 手工设定分数（`favor_set` 命令 / WebUI 改分）走**同一套预算**，不是绕过约束的后门；
> 初始化一个**新**档案时不受限。

## 四、快速开始

1. 把本目录放进 NekroAgent 插件目录，或在 NA WebUI 上传打包好的 zip；
2. **完全重启 NekroAgent**（钩子、路由与后台任务在启动时挂载）；
3. **设置 WebUI 访问密钥**（推荐，见第八节）：在 NA 插件配置里给 `WEBUI_ACCESS_KEY` 填一个密钥。
   不设也能用，但 WebUI 的写操作会被后端拒绝；
4. 打开 WebUI：`/plugins/<插件key>/`；
5. **写你自己的三档记忆**：编辑**插件数据目录**下 `backgrounds/` 里的 JSON，
   然后点重载（或让 AI 调「重新加载背景记忆」），无需重启容器。

> 包内的 `backgrounds/` 只是**首次运行的种子**，数据目录已存在时不会被覆盖；
> 升级插件也不会动你的记忆数据。
>
> 依赖：`Pillow` 仅排行榜卡片需要，缺失时自动回退纯文本，其余功能不受影响。

## 五、数据格式（本插件的核心配置面）

```
{插件数据目录}/backgrounds/
├── tier1/core.json     1 档·身份（每轮常驻）
├── tier2/lore.json     2 档·往事（提到才检索）
├── tier3/world.json    3 档·世界知识（不受门控）
└── favor.json          解锁门控配置
```

> **这个目录到底在哪（2.0.2）**：插件用 `plugin.get_plugin_data_dir()` 在**每次访问时**
> 解析路径，因此会跟随 NA 的账号上下文。原版 NA 镜像下它恒定返回同一个共享数据目录，
> 上面写的路径就是它；**账号化改造的镜像**下，有账号上下文时（消息处理 / 账号化的插件
> WebUI）返回该账号自己的 `<共享数据目录>/accounts/{账号}/`，每个账号各有一份
> `backgrounds/`，互不影响；没有账号上下文时仍是共享目录。
> **概览页会显示本次实际使用的数据目录**，以它为准，不要凭记忆找路径。

**条目字段**

| 字段 | 适用 | 说明 |
|---|---|---|
| `id` | 全部 | 条目标识（WebUI 与去重用） |
| `title` | 全部 | 标题（2/3 档也参与包含式去重） |
| `content` | 全部 | 正文，注入给模型的内容 |
| `weight` | 全部 | 权重，同档位内排序 / 截断依据 |
| `enabled` | 全部 | 是否启用 |
| `min_favor` | 1 / 2 档 | 好感度门槛（0=公开 / 20=亲近 / 60=偏爱） |
| `trigger` | 1 档 | 仅展示用（1 档不做关键词匹配） |
| `triggers` | 2 / 3 档 | 关键词列表，命中即注入；未命中走向量检索 |
| `familiarity` | 3 档 | `熟人` / `听说` / `仅传闻`，决定语气分寸 |

**最小示例**

```jsonc
// tier1/core.json —— 身份级，每轮都在
{
  "character": "示例角色",
  "tier": 1,
  "entries": [
    { "id": "who_i_am", "title": "我是谁", "weight": 5, "min_favor": 0, "enabled": true,
      "trigger": "（常驻）", "content": "我是示例角色……" }
  ]
}

// tier2/lore.json —— 提到才检索
{
  "character": "示例角色",
  "tier": 2,
  "entries": [
    { "id": "passerby_a", "title": "路人甲", "weight": 3, "enabled": true,
      "triggers": ["路人甲", "邻居", "好人"], "min_favor": 0,
      "content": "路人甲是个好人。上次我搬东西，他二话不说就来帮忙……" }
  ]
}

// tier3/world.json —— 世界知识，不受门控
{
  "character": "示例角色",
  "tier": 3,
  "entries": [
    { "id": "the_city", "title": "我住的城", "weight": 3, "enabled": true,
      "familiarity": "熟人", "triggers": ["这座城", "城里"],
      "content": "我住的城不大，一条主街走到底就是河边……" }
  ]
}
```

**favor.json（门控配置）**

```jsonc
{
  "enabled": true,
  "plugin_module": "nekro_persona",
  "store_key": "favorability_state",
  "stages": [
    { "max": -60, "name": "排斥", "unlock_hint": "只给最表面的回应" },
    { "max": -20, "name": "保留", "unlock_hint": "礼貌但克制" },
    { "max": 19,  "name": "中立", "unlock_hint": "公开层" },
    { "max": 59,  "name": "亲近", "unlock_hint": "可流露脆弱面" },
    { "max": 84,  "name": "偏爱", "unlock_hint": "可讲最私密的事" },
    { "max": 999, "name": "特别亲密", "unlock_hint": "关系已确立，语气最亲密（仍守角色边界）" }
  ],
  "stage_guides":     { "中立": "该档位的互动指引（会注入）" },
  "stage_guide_common": "所有档位共用的边界提醒",
  "rubric": { "header": "#好感度评估参考", "intro": "…", "items": [["+1~2", "普通友好互动"]] },
  "avoid":  { "header": "#暂时不想细说的事", "note": "…" }
}
```

> 随插件分发的示例（「路人甲是个好人」等）**仅用于演示格式**，请整份替换成你自己的人设。

## 六、LLM 沙盒方法

沙盒方法以**中文名**注册（下表「名称」列为模型看到的工具名），括号内为对应的 Python 函数名。

**记忆侧**

| 名称 | 类型 | 作用 |
|---|---|---|
| 重新加载背景记忆 | AGENT | 重载三档记忆 JSON（改完文件调用，无需重启） |
| 记笔记 | TOOL | **1.8.0**：记一条频道功能笔记（可设过期与好感门槛；原「记备忘录」更名并入 tier4 note） |
| 忘掉笔记 | TOOL | 删除笔记（标题支持模糊匹配；原「忘掉备忘录」更名） |
| 沉淀身份锚点 | TOOL | **1.7.0**：沉淀一条关于「我是谁」的全局身份锚点（永久、跨频道；受频率硬闸约束） |

**门控与关系侧**

| 名称 | 类型 | 作用 |
|---|---|---|
| 调整好感度 | BEHAVIOR | 按用户言行增减关系分并记录证据（受全部约束层限制） |
| 重设好感度档案 | BEHAVIOR | 覆盖式改写档案（描述字段），走同一套预算 |
| 删除好感度档案 | BEHAVIOR | 删除某用户档案 |
| 查看好感度档案 | AGENT | 查询某用户的完整档案 |
| 列出好感度档案 | AGENT | 列出本频道有档案的用户 |
| 好感度衰减检查 | AGENT | 手动结算一次衰减 |
| 好感度回升检查 | AGENT | 手动结算一次回升 |

**关于类型的选择**：`AGENT` 会在工具返回后**继续下一轮**，把结果交给模型接着说；
`TOOL` / `BEHAVIOR` 不延长回合——「记笔记」的说明里因此明确要求模型「记完后在同一次回复里正常回应对方」。
这样设计是为了省迭代预算、避免模型重复发言。

|---|---|

| 锚点记忆 | **1.7.0**：查看 / 删除 / 调核心度（salience）角色自己沉淀的身份锚点；顶部显示频率闸状态与配额；「导出 tier4.json」把这一世的生长痕迹**私有**存档（绝不进公开种子包） |
| 好感度档案 | 按频道浏览用户档案、改分、查看变动历史（客户端分页） |
| 注入预览 | 按频道与分数渲染**真实**注入文本，调参用；**检索实验**（1.5.0）：输入模拟对话，逐条看 2/3 档候选的分数 / 来源 / 门控 / 热度与去留原因 |

### 访问密钥（重要）

插件路由**不受 NA 全局鉴权保护**（任何能访问 NA 端口的人都能直接调它的接口），
所以从 1.4.1 起有一道强制约束：

- **配置了 `WEBUI_ACCESS_KEY`**：读写都要求密钥。前端会弹窗询问一次并记住，
  之后自动带上；也可手动在请求头里带 `X-WebUI-Key`。
- **没配置**：**只读放行，所有写操作一律 403**。
  这是为防止匿名请求改人设记忆与人格预设——不是 bug。

因此「概览」页的预算表单在未配置密钥时会**自动降级为只读**（按钮置灰并给出提示），
而不是等你改完才发现存不进去。

> 出于安全考虑，密钥**只接受请求头**，不再支持 `?key=` 查询参数
> （查询参数会进访问日志 / 浏览器历史 / Referer），校验用常数时间比较。

## 九、人设的备份与搬家

WebUI「规则与门控」页底部提供整包导出 / 导入：

- **导出**：把 `backgrounds/tier1|tier2|tier3/*.json`、`favor.json`、以及当前所有
  **人格预设（preset）文本**打成一个 zip，另附 `persona.bundle.json` 记录导出时间与条目数。
  适合入库版本管理，或换机器时整体搬走。
- **导入**：选择之前导出的 zip，**覆盖式**写回上述文件与预设文本。导入前会自动把当前文件
  备份到 `{数据目录}/persona_import_backups/<时间戳>/`；包内 JSON 结构不合法（例如
  `favor.json` 缺 `stages`、档位文件缺 `entries`）会**整体拒绝**，不会写坏现有数据。

> 只导入 backgrounds 而不动预设也可以——包内没有 `presets/*.md` 时跳过预设导入。

> **种子 vs 生长（1.7.0 起，2.0 完成分离并定为长期架构）**：上面这个 zip 是**种子包**（`GET /api/backup/export`）——只含手工策划的 tier1/2/3 + `favor.json` + 预设，
> 语义是「角色定义」，明确要公开 / 入库 GitHub / 版本化。tier4 生长数据**绝不进种子包**（它记录这一世的真实痕迹，属私密）。
>
> **1.9.0 新增独立的「生长包」**（WebUI「规则与门控 → 生长包」，或 `GET /api/growth/export`）：打包
> `tier4.json`（身份锚点 + 频道笔记）+ **各频道关系档案**（`archives.json`，按 chat_key 建索引；档案 blob 本身不含 chat_key，
> 用字典才无损）+ `.hit_stats.json`（热度）+ `_migrations.json` / `_channel_index.json`。关系档案此前**完全不进任何导出**，这是补上的真实迁移丢数据缺口。
>
> 两个包**彻底分离、各自 import、互不侵犯**（import 是 scope-aware 的）：
> - 种子包 `POST /api/backup/import`：只写 tier1/2/3/favor/presets，**不碰**生长数据。
> - 生长包 `POST /api/growth/import`：只写 tier4/关系档案，**不碰**种子；导入前把当前生长状态备份到 `{数据目录}/_growth_import_backups/<时间戳>/`。
>   ⚠️ 热度 sidecar（`.hit_stats.json`）**不随生长包迁移**：它是「本实例这一世的命中统计」，跨实例搬运会让排序基于别处的对话习惯，由导入实例自行累积（导出包里也不含它）。
>
> 频道枚举走 `DBPluginData.filter(plugin_key=…)`（store 的后端，天然覆盖全部有档频道，比 `_channel_index ∪ DBChatMessage` 更完备——这是实测对设计稿的更正）。
> 这样「做种留档」与「实例间迁移备份」两件事不再混在一个产物里，也避免运行时数据误传。

**检索文本的构成（2.0.1，默认全部保持旧行为）**

判断「有没有提到」用的是**最近若干条消息拼起来的原文**。下面几个开关决定这段文本从哪些消息里取。
默认全关；开启后能显著提升召回，尤其是**工具识别结果**——人脸识别出的角色名落库为系统消息，
原本完全不参与检索，于是「明明识别出来了却不注入」。

| 配置项 | 默认 | 说明 |
|---|---|---|
| `QUERY_INCLUDE_BOT` | `false` | 把角色自己的回复也纳入检索文本 |
| `QUERY_BOT_MAX` | `2` | 最多纳入最近几条回复；封顶以防「自我引用循环」占满扫描窗口 |
| `QUERY_INCLUDE_TOOL_FACTS` | `false` | 纳入系统消息（工具结果），**仅当其含已知触发词**；白名单，好感度回执 / msg_id 等噪声结构上进不来 |
| `QUERY_INCLUDE_SENDER_NAME` | `false` | 人类消息前加发送者群昵称，让「谁在说话」也成为检索依据；**角色自己的名字不加**（人格名常是触发词，加了会每轮自我触发） |

> 实测（36 个「识别出触发词名」的真实事件；判据 = 期望条目落在 top-K 内）：
> 旧行为 4/36 (11%) → 仅 `QUERY_INCLUDE_BOT` 24/36 (67%) → 仅 `QUERY_INCLUDE_TOOL_FACTS` 34/36 (94%)
> → 两者都开 **35/36 (97%)**。

**记忆生命周期（1.5.0，默认关闭）**

开启后 2/3 档按「作者 weight × 热度」排序：常被想起的记忆更稳，长期冷门的在超预算时优先让位。
**只影响排序与截断，绝不删除或改写你的内容**；高 weight 条目豁免；关闭时行为与不开此功能完全一致。
命中统计存在数据目录的 `.hit_stats.json`（独立 sidecar，可安全删除，删了只是计数归零）。

| 配置项 | 默认 | 说明 |
|---|---|---|
| `LIFECYCLE_ENABLED` | `false` | 总开关；关闭时零行为变化、不写 sidecar |
| `LIFECYCLE_HALF_LIFE_DAYS` | `30` | 多少天未命中后热度衰减到一半 |
| `LIFECYCLE_FLOOR` | `0.6` | 热度下限（0~1）；再冷也不会彻底消失 |
| `LIFECYCLE_PROTECT_WEIGHT` | `4` | weight ≥ 此值的条目完全豁免降权（保护核心设定） |
| `LIFECYCLE_REINFORCE_BONUS` | `10` | 每次命中回补的热度（×0.01，填 10 = 0.10） |

> **关于 0 值（1.6.3 修复）**：`LIFECYCLE_FLOOR=0`（冷门记忆可彻底冷却）、`LIFECYCLE_PROTECT_WEIGHT=0`
> （不豁免任何条目）、`LIFECYCLE_REINFORCE_BONUS=0`（命中不回补、纯衰减）都是**合法取值**，会被如实采用。
> 旧实现用 `x or 默认值` 判空，会把显式的 0 静默吞成默认（0→0.6 / 0→4 / 0→0.1），且概览页显示 0、
> 运行期却按默认生效——面板看到的与引擎实际用的对不上。1.6.3 起四处构造点统一为「仅缺失/None 才回落默认」。

> **预热说明（1.6.3）**：生命周期**关闭期间不累积命中**（关闭时零副作用、不写 sidecar 是刻意设计）。
> 因此首次开启时所有条目都是「冷」的（heat=floor），热度排序需要跑几轮、积累命中后才有区分信号。
> 这是预期行为，不是 bug；若想让排序立刻有意义，可先开启一段时间再依赖它。

> **1 档没有阈值 / 扫描项**（不参与检索）。**阈值越低越容易命中，噪声也越多**；
> 条目变多后噪声上限会上升，需要重新标定。三档预算互不影响。
>
> **阈值标定（1.5.0）**：`python scripts/calibrate_threshold.py --bg <数据目录>/backgrounds`
> 在真实嵌入上量化噪声天花板 / 语义密度 / 判别力，判断当前阈值偏松还是偏紧。
> 实测经验：人设库条目彼此语义相关、正负分布常重叠，此时**绝对阈值是弱杠杆**——
> top-1 命中率高就该靠排序（生命周期热度）而非一味抬阈值，抬过头会误杀正确条目。
>
> ⚠️ **后端一致性（1.6.3 修复）**：标定必须在**与生产检索相同的向量空间**里做，否则结论失真。
> 旧实现硬 import NA 内置 `embed_text`，即便你配了 `EMBED_PROVIDER=custom` 也拿 NA 空间标定 custom 检索——
> 结论全错且看不出错。1.6.3 起脚本自动读取 `<bg>/../config.yaml` 的 `EMBED_*`，custom 时注入到 memory、
> query 侧走 `_embed_query`（与条目侧同源），并在开头**打印实际后端与向量签名**供你核对。

## 十一、常见问题

**WebUI 里改不动、保存按钮是灰的 / 报 403**
没有配置 `WEBUI_ACCESS_KEY`。这是 1.4.1 起的安全约束：插件路由不受 NA 全局鉴权保护，
匿名不得写。到 NA 插件配置里给本插件设一个访问密钥并保存，刷新页面即可（浏览器会弹窗问一次）。

**改了 JSON 但没生效**
数据目录与包内不是同一份（包内只是种子）。确认改的是**插件数据目录**下的 `backgrounds/`，
然后调用「重新加载背景记忆」或在 WebUI 点重载。概览页会显示实际使用的数据目录。

**2 档 / 3 档检索不到**
先看 `triggers` 关键词是否覆盖了实际说法；未命中会走向量检索，阈值由 `TIER2_SIM_THRESHOLD` /
`TIER3_SIM_THRESHOLD` 控制。条目变多后噪声上限会上升，需要重新标定阈值。

**2 档明明有内容却没注入**
可能是单轮预算被一条过长记忆吃满了。2 档超预算时会**跳过**该条并继续尝试后续条目（不是中止），
日志里会记 `2 档超出单轮预算 … 跳过 N 条过长记忆`。缩短 `content` 或提高 `TIER2_MAX_CHARS`。

**1 档把预算吃满了**
1 档硬上限默认 2000 字符，超出会按 `weight` 降序截断并写日志。身份级内容放不下的，
应该降档到 2 档（改成「提到才检索」），或提高 `TIER1_MAX_CHARS`。

**角色把不该说的说了**
在 `favor.json` 的 `stage_guide_common` 里补充边界约束；
2/3 档的 `content` 只写「事实」，不要写「你要怎么回答」这类元指令。

**关系档案被写脏**
用 `FAVOR_FORBIDDEN_PROFILE_WORDS` 配置禁写词（正文命中替换为「群友」、标签命中丢弃）。

**好感度为什么加不上去**
约束层在起作用：单次上限、同用户间隔、每日上限、边际递减、理由是否具体，
以及「索要式加分」会被直接拒绝（分数应随真实言行自然变化）。手工 `favor_set` 也受同一套预算限制。

**升级插件会不会覆盖我的记忆**
不会。数据在插件数据目录，升级只替换插件包；包内 `backgrounds/` 仅在数据目录不存在时作种子复制。

> 注意：新增的档位（如 1.4.2 的「特别亲密」）**只会进新部署**，

## 十二、实现说明

本插件由三层组成，全部为本项目自有实现：

- **记忆层**（`memory.py`）：三档 JSON 的加载与 mtime 热重载、嵌入向量化与降级、
  关键词优先 + 向量兜底的检索、按档位切分的字符预算与渲染。
  三档预算与阈值**全部经参数注入**（`tier1_settings` / `tier2_settings` / `tier3_settings`），
  模块内没有硬编码的魔法数字，便于测试与单点调整。
  1.5.0 起检索链路**保留相似度分数**（`ScoredEntry`）并与 `ctx` 解耦出纯文本核心
  （`_match_tier2_text` / `_match_tier3_text`），门控抽成纯函数 `apply_gating`——
  因此可离线单测、可被 WebUI「检索实验」与 `scripts/calibrate_threshold.py` 直接驱动。
  可选的**记忆生命周期**（`LIFECYCLE_ENABLED`，默认关）按「weight × 热度」排序，
  命中统计存独立 sidecar `.hit_stats.json`，只影响排序、绝不改写作者内容。
  1.6.0 起嵌入后端**可插拔**（`EMBED_PROVIDER=na/custom`）：条目侧与查询侧统一经
  `_embed_entries` / `_embed_query` 路由，保证同源；`_embed_signature` 含后端身份，
  换模型时向量缓存自动整体作废重建，杜绝新旧向量混算。custom 走 OpenAI 兼容端点
  （httpx 批量 + `gen_openai_embeddings` 逐条兜底），配置不全时安全回落 NA 内置。
  1.6.2 起补齐**查询侧嵌入缓存**：条目侧向量早有磁盘缓存，但每轮对话的 query 向量
  旧实现现算现扔，且同一轮里 2/3 档各读一次库、各嵌一次几乎相同的最近文本。现在
  `render_memory_block` 按 `scan_msgs` **单次取最近文本**（2/3 档相同时复用同一次读库），
  query 向量再经 `_embed_query` 的**短 TTL + LRU 内存缓存**（按签名隔离，换模型自动失效）
  去重——多数轮次的嵌入 API 调用从 2 次降到 1 次、连续同话题轮次降到 0 次，
  对限流较严的端点尤其省。纯内存不落盘、不改磁盘缓存格式，golden 验证渲染逐字节不变。
  1.6.3 修了一批静默失真：`lifecycle_settings` 及三处配置构造点改用「仅 None 才回落默认」，
  合法的 `floor/protect_weight/reinforce_bonus=0` 不再被 `x or 默认` 吞掉、概览显示与运行期同源；
  `_render_tier3` 超预算由 `break` 改 `continue`（对齐 2 档，长条不再阻断其后条目）；
  渲染器回传**实际注入集**，`_bump_hits` 只给真进输出的条目涨热度（超预算被跳过的长条不再虚涨）；
  custom 端点连续失败置**降级标志**并告警（`embed_health()` → 概览页横幅），刻意不混空间回落 NA。
- **档案层**（`plugin.py`）：频道级关系档案与变动记录的数据模型、状态存取、
  按分数换算档位、按 `min_favor` 过滤可讲范围、衰减与回升结算、防刷分约束。
  所有写入路径都经过 **per-chat_key 异步锁**——档案是 read-modify-write 的单个 blob，
  聊天消息、WebUI 改分与后台衰减结算并发时若不上锁会 last-writer-wins 丢分。
- **生长层**（`tier4.py`，1.7.0；1.8.0 加入 note）：独立于阶梯记忆的运行时可追加层，单一全局文件 `backgrounds/tier4.json`，
  每条带 `kind`（anchor|note）+ `scope`（global|chat_key）。**只读写 tier4.json，绝不碰 tier1/2/3/favor.json**（铁律②）。
  一把全局写锁（写稀疏，频率闸限死；读走 mtime 缓存、不加锁）。`write_anchor` 在同一把锁内完成
  「频率闸 → 去重 → 落库 → bump meta」的 read-modify-write，避免嵌套非重入锁死锁。
  注入用 **salience 单调填充**（预检剔除单条超预算者 → salience 降序 → 一旦注入过更低档便不再回填更高档），
  保证「核心锚点永不因低档挤占而消失」这条不变量。另自维护 `backgrounds/_channel_index.json`
  （`PluginStore` 无枚举接口，为阶段 C 生长包导出铺路）。文案留在 `plugin.py`，本模块只做确定性的存储与算法。
  **1.8.0 阶段 B**：`kind=note` 接替旧「备忘录」——`render_note_block` 是对旧 `_render_memo_block` 的**逐字复刻**
  （同过滤/排序/选取/`· 【标题】内容`格式/预算 break/引导兜底），旧 memo 子系统（`ChannelMemo`、`_memo_*`、旧注入块）
  已**干净移除**（不注释）；配置键沿用 `MEMO_*`（不重命名以免重置你已调过的值）。首载由 `plugin._migrate_memos_on_load()`
  一次性把各频道 `ChannelArchive.memos` 折进 tier4 note：枚举走 `DBPluginData.filter(plugin_key=…)`（覆盖全部有档频道，
  比 `_channel_index` 全）；**幂等**（跳过 `memos_migrated` 的 blob、note id = `note_{原 memo id}` 天然去重）、
  **可回滚**（原始 blob 备份到 `backgrounds/_pre_migration/`）、**失败不丢**（tier4 写失败则不标记不清空、下次重试）；
  全程写 `backgrounds/_migrations.json` 报告（删了旧子系统后唯一能审计「某频道到底迁没迁」的来源）。
- **展示层**（`webui.py` + `webui.html` + `card.py`）：七页签管理台（含「锚点记忆」）、接口若干、
  排行榜卡片渲染。`GET /api/tier4`、`POST /api/tier4`（delete/salience）、`GET /api/tier4/export`（私有导出）；
  **1.9.0** 导出分离：`GET /api/growth/export`、`POST /api/growth/import`（生长包，scope-aware，不碰种子），与现有
  `GET /api/backup/export`、`POST /api/backup/import`（种子包）并列。

依赖 NekroAgent 提供的插件 API：`NekroPlugin` 与 `mount_*` 装饰器、`ConfigBase` 配置系统、
`store` 键值存储、命令与沙盒方法注册。

### 2.2.17

**修 2.2.15 的两个致命回归（密钥框不可见 / 重放错对象）+ 四项残留**

- **密钥框被嵌进确认框里，401 时完全不可见**（2.2.15 引入）：`<dialog id="keyDlg">` 的插入
  锚点选在了 `#confirmDlg` 的 `</dialog>` **之前**，于是它成了确认框的子元素 —— 注释却写着
  「必须是独立的 `<dialog>`」。确认框常态关闭时子 dialog 不渲染（实测 0×0），用户在 401 时
  根本看不到输入框，「保存并重试」整条链路不可用。现已移出，三个 dialog 都是顶层兄弟节点
  （按标签配对验证：`{dialog:0, keyDlg:0, confirmDlg:0}`）。
- **重放的是最后一次 401，不是用户的操作**（2.2.15 引入）：`_setAuthPending` 无条件覆盖 ——
  保存条目 POST 401 后，处理函数紧跟的 `loadMemory()` 也 401，把 pending 覆写成列表加载；
  保存密钥后重放的是 GET，用户那条保存被静默丢弃（还因为列表刷新显得「已生效」）。
  现在 pending 带 `sticky` 标记：**写操作（mutate/postAction）优先，GET 的 401 不覆盖**，
  密钥框里也会写明「这是你的写操作，不会被列表刷新覆盖」。实测：写 401 → GET 401 → 重放仍是
  写操作；写操作被消费后新的 GET 才能登记。
- **F8 锚点核心度圆点键盘无响应**：圆点带 `role="button" tabindex="0"`，但 Enter/Space 之前
  不做任何事。现在 Enter/Space = 前进一档（到顶回 1），←/→/↑/↓ 直接增减；点击与键盘共用
  `setAnchorSalience()`。
- **只发 `stage_guides` 不带 `stages` 时孤儿指引不过滤**：`names` 为空集 → `if names and …`
  短路，档位已改名/删除的指引全部保留。现在读一次磁盘现有档位名再过滤
  （实测：只提交 `{真实档位: …, 已删除的档位: …}` → 落盘只剩真实档位那条）。
- **`dedup_materials` 从死代码变成真在用**：素材入桶前按归一化文本去重（桶是 500 条上限，
  重复 reason 白占额度），采集计数也改用去重后的条数。
- **`/api/heat/reset` 的响应回宿主机绝对路径**：`"dir"` 现在也走 `_public_detail` → `<数据目录>`。
  顺带补 `memory.reload_hit_stats()` 并接进 `/api/reload`：此前 `ensure_loaded(force=True)` 不会
  重读命中统计 sidecar，内存为空时「重载背景记忆」读不回来，而下一次去抖落盘又会用空内存
  覆盖文件。

### 2.2.16

**侧栏不再假设顶栏 67px / statusLine 默认转义 / 清死代码 / 门槛钳上限 / 热度重置加锁**

- **侧栏 sticky 的 1px 硬编码**：`.sidebar { top: 67px }` 对应的前提是顶栏恒为 66px —— 窄屏 +
  长插件名让顶栏换行后，侧栏会和顶栏重叠或露缝。现在改用 `top: var(--topbar-h, 67px)` /
  `height: calc(100vh - var(--topbar-h, 67px))`（桌面与移动端两处），`--topbar-h` 由
  `initTopbarHeight()` 用 `ResizeObserver` 实测顶栏高度写入，窗口 resize 也重算。
- **`statusLine(name, value)` 的 value 不转义**：以前由调用方自己 `esc`，是「漏一处就成注入点」
  的埋雷式 API。现在 `statusLine` 内部转义，需要放标记的地方显式用新增的 `statusLineHtml`
  ——「要 HTML」成为一个看得见的决定。顺带把 `防白嫖护栏` 那处调用方 `esc` 去掉，避免双重转义。
- **死代码清理**：`.rubric-row` / `.rubric-row-head` / `.rubric-dot` / `.rubric-key` /
  `.rubric-desc` 在标记里早已不存在（实际用 `.rubric-item`），连 `rubricDotPulse` 关键帧一起删
  （选择器组、玻璃层列表、`no-ambient-fx` 列表里的引用同步清掉）。`withBusy` 里恢复文本的条件
  `if (textContent !== oldText && textContent === '')` 恒假（loading 是 CSS `::after` 画的，
  没人改 textContent），改成 `if (!btn.textContent)`。
- **`POST /api/entry` 的 min_favor 只钳 ≥0**：前端钳了上限，直接调 API 可以写入超过
  `MAX_ABS_SCORE` 的门槛 —— 这种条目**永远不会解锁**。现在 modify 与 `/api/entry/new` 两处都
  钳到 `helpers["max_abs_score"]()`（实测 9999 → 100），并删掉已被 `max(0,…)` 覆盖的死校验。
- **`POST /api/heat/reset` 不持锁**：与检索路径的 `_bump_hits` 存在「刚累加的计数被空字典覆盖」
  的理论竞态。现在 `memory` 侧新增 `_HIT_LOCK`（`RLock`，reset 持锁时会再进 `_save_hit_stats`）
  与 `reset_hit_stats()`，WebUI 只调这个接口；`_bump_hits` 的读改写也在锁内
  （实测 8 线程 × 20 条 × 1 次 = 160，一条不丢）。

### 2.2.15

**「保存并重试」真的重试 + 弹窗打开时提示能看见 + 密钥框不再抢走弹窗**

- **「保存并重试」以前不重试**：`load`/`mutate`/`postAction` 遇 401 只弹密钥框然后 `return null`
  —— 触发 401 的那次 POST **被静默丢弃**，保存密钥后只重跑当前页的 GET loader。用户点「删除」
  → 填密钥 → 看到列表刷新，就以为删成功了，条目其实还在。现在包装层把这次调用登记到
  `_authPending`（保留 path/body/opts，重放走完整 `mutate`，`okMsg` 等语义一并保留），
  密钥框的「保存并重试」保存后真的重放它；成功提示「密钥已保存，已重试：…」。
  另外 401 当场会明说 **「本次操作没有执行」**，不再让人误判。
- **填错密钥不会来回弹框**：重放期间再遇 401 直接抛给调用方并提示「密钥仍被拒绝」，
  不重新弹框（`_authReplaying` 标志）；取消/Esc/点遮罩关闭都会清掉 pending，避免下次 401
  误用陈旧重放。
- **密钥框会抢走正在用的弹窗**：以前复用 `#dialog`，401 一到就把「重置热度 / 档案详情 /
  确认流程」的内容覆写掉，按钮的 loading/禁用状态也一起丢。现在是独立的 `#keyDlg`，
  两层自然堆叠；密钥框里还会明确写出「保存后会自动重试：<接口>」。
- **弹窗打开时 toast 被遮罩压暗**：原生 `dialog.showModal()` 进入 top layer，普通 `z-index`
  永远画不过它（`::backdrop` 还有 `blur(12px)` + 55%~66% 暗色）—— 档案弹窗里点「改分」的
  成功/上限提示基本不可读。现在 `.toast-region` 改为 `popover="manual"`，每次 toast 时重新
  `showPopover()` 把它排到 dialog 之上（后加入 top layer 的在上）；UA 默认样式（`inset:0`/
  `margin:auto`/边框/背景）已显式清掉，空队列时 `hidePopover()` 收起。
  `@supports selector(:popover-open)` 兜住旧浏览器，退回原来的 z-index 行为。
- **撒花同理**：弹窗开着时粒子改挂到 `dialog[open]` 里（否则被 top layer 挡在背后，
  看着像没触发）。
