# 三档背景记忆 (nekro_persona)

> NekroAgent 插件 · 让角色记住**她是谁、经历过什么、这个世界是什么样的**
> 分层注入 + 按需检索 + 硬预算；**好感度是解锁标尺**——关系没到，有些事她就还不想说。

版本 **1.3.0**　作者 **NTidal**　许可 **MIT**

---

## 一、为什么分三档

提示词预算是有限的，而「该记住的事」重要性差别极大：基础设定每轮都得在，几十条往事不可能每轮都塞进去。

所以按**「什么时候该想起来」**分档：

| 档位 | 内容性质 | 何时注入 | 预算 | 匹配方式 | 好感度门槛 |
|---|---|---|---|---|---|
| **1 档 · 身份** | 她是谁、日常、基本设定 | **每轮直接注入** | 硬上限 2000 字符 | 不匹配，全量注入 | `min_favor` |
| **2 档 · 往事** | 她亲历的细节 | **提到才检索** | 单轮 ≤2 条 / 500 字符 | `triggers` 关键词优先，未命中走向量（阈值 0.35） | `min_favor` |
| **3 档 · 世界知识** | 她之外的人 / 地点 / 势力 / 术语 | **提到才检索** | 单轮 ≤3 条 / 700 字符 | 同上 | **不受门控** |

几个关键取舍（都是实测调出来的）：

- **2/3 档的检索 query 用「最近消息原文」，不用 LLM 生成**——LLM 生成的 query 是文档腔，实测召回 0.32 vs 原文 0.49
- **2 档偏精确**：1 档已经兜住身份，2 档漏召回不致命，误召回反而会把话题带偏
- **3 档不受好感度门控**：世界常识不该因为不熟就不说；但用 `familiarity`（熟人 / 听说 / 仅传闻）控制语气分寸，角色不该「全知」
- **1 档静态、2/3 档多数轮次为空** → 系统提示词前缀缓存友好

## 二、一轮对话里发生了什么

```
用户消息
   │
   ├─ 1 档：全量注入（身份级，超预算按 weight 截断）
   │
   ├─ 2/3 档：用最近消息原文做匹配
   │     ├─ triggers 关键词命中 → 直接取用
   │     └─ 未命中 → 向量检索（阈值 0.35，独立预算，3 档不与 2 档抢 top-N）
   │
   ├─ 门控过滤（见第三节）
   │     ├─ 达到 min_favor → 进正文
   │     └─ 未达到       → 列入「暂时不想细说的事」
   │
   └─ 渲染成「#你的记忆」「#你知道的事」两段，交给模型
```

记忆数据改完不需要重启：WebUI 点重载，或让 AI 调用 `reload_persona_memory`。

## 三、好感度：解锁标尺

好感度在本插件里的**主要作用是决定「哪些事现在能讲」**：

| 机制 | 说明 |
|---|---|
| `min_favor` | 每条 1/2 档记忆的门槛（0=公开 / 20=亲近 / 60=偏爱）。没到就进不了正文 |
| `stages` | 分数落在哪个区间，决定当前档位名 |
| `stage_guides` | 各档位的**互动指引**（注入给模型，调节亲密度与语气） |
| `avoid` | 未达标记忆改写成「暂时不想细说的事」，由模型自己把握怎么带过 |

分数由 AI 在对话中**自主调整**（`adjust_favorability`），也可用群聊命令手动干预。

档案层与记忆层一样，都是本插件自己的实现：频道级档案的数据模型与状态存取、
按分数换算档位、按 `min_favor` 过滤可讲范围、衰减与回升结算、防刷分约束，
以及六条群聊命令与对应的 LLM 工具。

## 四、快速开始

1. 把本目录放进 NekroAgent 插件目录，或在 NA WebUI 上传打包好的 zip；
2. **完全重启 NekroAgent**（钩子、路由与后台任务在启动时挂载）；
3. 打开 WebUI：`/plugins/<插件key>/`；
4. **写你自己的三档记忆**：编辑**插件数据目录**下 `backgrounds/` 里的 JSON，
   然后点重载（或让 AI 调 `reload_persona_memory`），无需重启容器。

> 包内的 `backgrounds/` 只是**首次运行的种子**，数据目录已存在时不会被覆盖；
> 升级插件也不会动你的记忆数据。
>
> 依赖：`Pillow` 仅排行榜卡片需要，缺失时自动回退纯文本，其余功能不受影响。

## 五、数据格式（本插件的核心配置面）

```
{插件数据目录}/backgrounds/
├── tier1/core.json     1 档·身份（每轮常驻）
├── tier2/lore.json     2 档·往事（提到才检索）
├── tier3/world.json    3 档·世界知识（不受门控）
└── favor.json          解锁门控配置
```

**条目字段**

| 字段 | 适用 | 说明 |
|---|---|---|
| `id` | 全部 | 条目标识（WebUI 与去重用） |
| `title` | 全部 | 标题（2/3 档也参与包含式去重） |
| `content` | 全部 | 正文，注入给模型的内容 |
| `weight` | 全部 | 权重，同档位内排序 / 截断依据 |
| `enabled` | 全部 | 是否启用 |
| `min_favor` | 1 / 2 档 | 好感度门槛：0=公开 / 20=亲近 / 60=偏爱 |
| `trigger` | 1 档 | 仅展示用（1 档不做关键词匹配） |
| `triggers` | 2 / 3 档 | 关键词列表，命中即注入；未命中走向量检索 |
| `familiarity` | 3 档 | `熟人` / `听说` / `仅传闻`，决定语气分寸 |

**最小示例**

```jsonc
// tier1/core.json —— 身份级，每轮都在
{
  "character": "示例角色",
  "tier": 1,
  "entries": [
    { "id": "who_i_am", "title": "我是谁", "weight": 5, "min_favor": 0, "enabled": true,
      "trigger": "（常驻）", "content": "我是示例角色……" }
  ]
}

// tier2/lore.json —— 提到才检索
{
  "character": "示例角色",
  "tier": 2,
  "entries": [
    { "id": "passerby_a", "title": "路人甲", "weight": 3, "enabled": true,
      "triggers": ["路人甲", "邻居", "好人"], "min_favor": 0,
      "content": "路人甲是个好人。上次我搬东西，他二话不说就来帮忙……" }
  ]
}

// tier3/world.json —— 世界知识，不受门控
{
  "character": "示例角色",
  "tier": 3,
  "entries": [
    { "id": "the_city", "title": "我住的城", "weight": 3, "enabled": true,
      "familiarity": "熟人", "triggers": ["这座城", "城里"],
      "content": "我住的城不大，一条主街走到底就是河边……" }
  ]
}
```

> 随插件分发的示例（「路人甲是个好人」等）**仅用于演示格式**，请整份替换成你自己的人设。

**favor.json（门控配置）**

```jsonc
{
  "enabled": true,
  "plugin_module": "nekro_persona",
  "store_key": "favorability_state",
  "stages":       [ { "max": 19, "name": "中立", "unlock_hint": "公开层" } ],
  "stage_guides": { "中立": "该档位的互动指引（会注入）" },
  "rubric":       { "header": "...", "intro": "...", "items": [["+1~2", "普通友好互动"]] },
  "avoid":        { "header": "#暂时不想细说的事", "note": "..." },
  "stage_guide_common": "所有档位共用的边界提醒"
}
```

## 六、LLM 工具

**记忆侧**

| 工具 | 类型 | 作用 |
|---|---|---|
| `reload_persona_memory` | AGENT | 重载三档记忆 JSON（改完文件调用，无需重启） |
| `save_memo` | TOOL | 记一条频道备忘（可设过期与好感度门槛） |
| `forget_memo` | TOOL | 删除备忘 |

**门控与关系侧**

| 工具 | 类型 | 作用 |
|---|---|---|
| `adjust_favorability` | BEHAVIOR | 按用户言行增减关系分并记录证据（受全部约束层限制） |
| `set_favorability_profile` | BEHAVIOR | 改写档案的稳定印象 / 互动提示 / 标签（不动分数） |
| `remove_favorability_profile` | BEHAVIOR | 删除某用户档案 |
| `get_favorability_profile` | AGENT | 查询某用户的完整档案 |
| `list_favorability_profiles` | AGENT | 列出本频道有档案的用户 |
| `run_favorability_decay` | AGENT | 手动执行一次衰减结算 |
| `run_favorability_recover` | AGENT | 手动执行一次回升结算 |

**关于类型的选择**：`AGENT` 会在工具返回后**继续下一轮**，把结果交给模型接着说；
`TOOL` / `BEHAVIOR` 不延长回合——`save_memo` 的说明里因此明确要求模型「记完后在同一次回复里正常回应对方」。
这样设计是为了省迭代预算、避免模型重复发言。

## 九、人设的备份与搬家（1.3.0）

WebUI「规则与门控」页底部提供整包导出 / 导入：

- **导出**：把 `backgrounds/tier1|tier2|tier3/*.json`、`favor.json`、以及当前所有
  **人格预设（preset）文本**打成一个 zip，另附 `persona.bundle.json` 记录导出时间与条目数。
  适合入库版本管理，或换机器时整体搬走。
- **导入**：选择之前导出的 zip，**覆盖式**写回上述文件与预设文本。导入前会自动把当前文件
  备份到 `{数据目录}/persona_import_backups/<时间戳>/`；包内 JSON 结构不合法（例如
  `favor.json` 缺 `stages`、档位文件缺 `entries`）会**整体拒绝**，不会写坏现有数据。

> 只导入 backgrounds 而不动预设也可以——包内没有 `presets/*.md` 时跳过预设导入。

## 十、配置项

**三档记忆**

| 配置项 | 默认 | 说明 |
|---|---|---|
| `TIER3_ENABLED` | `true` | 关闭后完全不检索 / 注入 3 档 |
| `TIER3_MAX_ENTRIES` | `3` | 3 档单轮最多注入条数 |
| `TIER3_MAX_CHARS` | `700` | 3 档单轮字符预算 |
| `TIER3_SIM_THRESHOLD` | `0.35` | 3 档向量检索阈值（条目变多后需重新标定） |
| `TIER3_SCAN_MSGS` | `6` | 判断「是否提到」时扫描的最近消息条数 |

> 1/2 档的预算与阈值目前是代码常量（`memory.py`）：1 档 2000 字符、2 档 ≤2 条 / 500 字符、阈值 0.35、扫描 6 条。

**解锁门控与关系**

| 配置项 | 默认 | 说明 |
|---|---|---|
| `DEFAULT_SCORE` | `0` | 新用户档案的默认评分 |
| `MAX_ABS_SCORE` | `100` | 评分绝对值上限 |
| `MAX_EVENT_HISTORY` | `8` | 每份档案保留的变动记录条数 |
| `PROMPT_EVENT_LIMIT` | `3` | 注入关系卡时展示的最近变动条数 |
| `GROUP_OVERVIEW_LIMIT` | `3` | 无明确触发用户时，回退展示的档案摘要数 |
| `MAX_TAGS` | `6` | 每份档案的关系标签上限 |
| `DECAY_ENABLED` | `true` | 长时间不互动自动降温 |
| `DECAY_INTERVAL_HOURS` | `24` | 超过该时长未互动触发一次衰减 |
| `DECAY_PERCENT` | `3` | 每次按当前分数扣除的百分比（向上取整） |
| `DECAY_KEEP_TIER` | `true` | 未超过档位保底时长时不跌破当前档位下界 |
| `DECAY_TIER_GRACE_HOURS` | `168` | 档位保底时长（超时后逐级解锁） |
| `RECOVER_ENABLED` | `true` | 负分随时间回升 |
| `RECOVER_INTERVAL_HOURS` | `12` | 回升触发间隔 |
| `RECOVER_PERCENT` | `5` | 每次按负分绝对值回升的百分比（至少 +1，封顶 0） |
| `FAVOR_MAX_SINGLE_DELTA` | `5` | 单次调整绝对值上限，超出自动钳制 |
| `FAVOR_MIN_INTERVAL_MINUTES` | `120` | 同一用户两次调整的最小间隔 |
| `FAVOR_MAX_DAILY_GAIN` | `5` | 同一用户每天最多净加分 |
| `FAVOR_MAX_DAILY_LOSS` | `10` | 同一用户每天最多净扣分 |
| `FAVOR_MARGINAL_DECAY` | `true` | 边际递减：分数越高同样行为加分越少 |
| `FAVOR_REQUIRE_CONCRETE_REASON` | `true` | 理由只有氛围词、无具体行为时不予加分 |
| `FAVOR_FORBIDDEN_PROFILE_WORDS` | 空 | 档案禁写词（额外）：正文命中替换为「群友」，标签命中丢弃 |

**备忘录**

| 配置项 | 默认 | 说明 |
|---|---|---|
| `MEMO_ENABLED` | `true` | 启用频道备忘录 |
| `MEMO_GUIDE_ALWAYS` | `true` | 常驻注入「什么时候该记」的引导 |
| `MEMO_MAX_ITEMS` | `80` | 单频道备忘上限（超出拒绝写入） |
| `MEMO_MAX_CONTENT_CHARS` | `400` | 单条备忘内容上限 |
| `MEMO_INJECT_RECENT` | `2` | 最近更新的几条每轮注入 |
| `MEMO_INJECT_MATCHED` | `3` | 话题命中时额外注入的条数 |
| `MEMO_INJECT_CHARS` | `900` | 备忘录单轮字符预算 |
| `MEMO_DEDUP_MIN_KEY_LEN` | `2` | 包含式去重的最短标题长度 |

**排行榜卡片 / WebUI**

| 配置项 | 默认 | 说明 |
|---|---|---|
| `RANK_HIDE_EMPTY` | `true` | 隐藏无任何记录的空档案 |
| `RANK_CARD_QUALITY` | `1` | 渲染精度档位（超采样倍率） |
| `RANK_CARD_SCALE` | `0.0` | 自定义超采样倍率；>0 时忽略精度档位 |

## 十一、常见问题

**改了 JSON 但没生效**
数据目录与包内不是同一份（包内只是种子）。确认改的是**插件数据目录**下的 `backgrounds/`，
然后调用 `reload_persona_memory` 或在 WebUI 点重载。概览页会显示实际使用的数据目录。

**2 档 / 3 档检索不到**
先看 `triggers` 关键词是否覆盖了实际说法；未命中会走向量检索，阈值由 `TIER3_SIM_THRESHOLD` 控制。
条目变多后噪声上限会上升，需要重新标定阈值。

**1 档把预算吃满了**
1 档硬上限 2000 字符，超出会按 `weight` 降序截断并写日志。身份级内容放不下的，
应该降档到 2 档（改成「提到才检索」）。

**角色把不该说的说了**
在 `favor.json` 的 `stage_guide_common` 里补充边界约束；
2/3 档的 `content` 只写「事实」，不要写「你要怎么回答」这类元指令。

**关系档案被写脏**
用 `FAVOR_FORBIDDEN_PROFILE_WORDS` 配置禁写词（正文命中替换为「群友」、标签命中丢弃）。

**升级插件会不会覆盖我的记忆**
不会。数据在插件数据目录，升级只替换插件包；包内 `backgrounds/` 仅在数据目录不存在时作种子复制。

**排行榜不出图**
需要 `Pillow` 与可用的中文字体。日志会说明是缺库还是缺字体，也可用 `RANK_CARD_FONT` 指定。
渲染失败自动回退纯文本，不影响功能。

**好感度为什么加不上去**
约束层在起作用：单次上限、同用户间隔、每日上限、边际递减、理由是否具体，
以及「索要式加分」会被直接拒绝（分数应随真实言行自然变化）。

## 十二、实现说明

本插件由三层组成，全部为本项目自有实现：

- **记忆层**（`memory.py`）：三档 JSON 的加载与 mtime 热重载、嵌入向量化与降级、
  关键词优先 + 向量兜底的检索、按档位切分的字符预算与渲染
- **档案层**（`plugin.py`）：频道级关系档案与变动记录的数据模型、状态存取、
  按分数换算档位、按 `min_favor` 过滤可讲范围、衰减与回升结算、防刷分约束
- **展示层**（`webui.py` + `webui.html` + `card.py`）：六页签管理台、19 条接口、
  排行榜卡片渲染

依赖 NekroAgent 提供的插件 API：`NekroPlugin` 与 `mount_*` 装饰器、`ConfigBase` 配置系统、
`store` 键值存储、命令与沙盒方法注册。
